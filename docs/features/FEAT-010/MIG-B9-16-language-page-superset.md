## 1. Goal

`/docs/language`, which the introduction page names as "the whole grammar",
stops describing the SCSS subset that MIG-B9-13 deleted. It says what a
`.uxdsl` file is since DEC-01: Dart Sass compiles it first, all of SCSS, and
UXDSL resolves its words in Sass's output; `uxdsl/postcss` alone compiles CSS
plus UXDSL and no Sass. Every example on the page compiles through the route
the harness gives it, and no code the catalog lacks is named.

## 5. Contract

The public entry points are the page as the playground serves it
(`/docs/language`, built by `next build`), the doc-examples harness
(`npm run verify:doc-examples`, `scripts/doc-examples.test.js`) and
`npm test`. Line numbers are `f855765`'s; MIG-B9-20 moves them, so the
passages are named by their text.

- **C1 — The subset section becomes the superset section.** The section
  that starts at `<h2 id="scss">` (lines 107–132) is replaced. The heading
  keeps `id="scss"`, so a link to `/docs/language#scss` still lands on it, and
  no longer says "subset". The section says:
  1. `uxdsl build`, `uxdsl/vite` and `uxdsl/webpack` compile a `.uxdsl` file
     with `compile()`: Dart Sass compiles it first, as Dart Sass defines SCSS
     (`@use` and `@forward`, `@mixin`/`@include` with keyword and variadic
     arguments and `@content`, `@function`, maps and lists,
     `@if`/`@else if`/`@each`/`@for`/`@while`, `@extend` with `%placeholder`,
     the `sass:` modules, nesting and `&`), and UXDSL resolves its own words
     in Sass's output; a token can be a variable's or a map's value, a mixin
     argument, or what `@each` and `@if` pick. `@import` of a partial still
     loads it, with Dart Sass's `[import]` deprecation as `UXD_SASS_WARNING`;
     `@use` does not warn. This replaces line 108's first sentence and the
     table's limits (lines 113–119).
  2. The qualified sentence of the owner's decision on MIG-B9-15's flag 1, as
     the package README words it: every SCSS file is a valid UXDSL file,
     except in three cases `compile.md` documents (a `$variable` Sass keeps as
     written fails as `UXD_SASS_CONTEXT`; text Sass prints that is not CSS
     fails as a parse error; a project function named with the Sass stage's
     internal prefix `uxdsl-probe-` can change the output).
  3. A token is a string to Sass: a Sass function that needs a color or a
     number fails on one as `UXD_SASS` (`darken(palette(primary.main), 10%)`),
     and the operation is written in CSS instead (a Palette alpha such as
     `palette(primary.main, 0.5)`, `color-mix()`, `calc()`). This replaces line
     125's claim that Sass color and math functions are refused.
  4. `uxdsl/postcss` used alone compiles CSS plus UXDSL and no Sass (DEC-05):
     a Sass construct reaching it fails as `UXD_SASS_CONTEXT`, naming the fix

## 7. Approach and traps

Non-normative.

- Write the examples first, run the harness on this page alone (§4's
  `verifySurfaces` line), then write the prose around them.
- Model the content on `compile.md`'s "Sass inside `compile()`" and the
  package README's "From SCSS", in fewer words: the page states the rules and
  links the guide for the detail. The link is an `<a href={…}
  target="_blank" rel="noopener noreferrer">` built from `GITHUB_URL`, as
  the home page builds its GitHub link; no host is written by hand.
- **The harness's rules for a `.tsx` page:**
  - The fence decides the route: `language-scss` goes through `compile()`,
    `language-css` through the plugin alone. The `UXD_SASS_CONTEXT` example
    must be a `css` fence; the `UXD_SASS` one a `scss` fence.
  - A `compile()` example documents at most one error, on its own line, and
    must compile without that line.
  - An example without UXDSL syntax is never collected, so it goes unchecked
    silently: give every new example a token, a responsive value or a
    directive.
  - A template literal that holds `${` is skipped silently too. Sass's `#{$x}`
    is safe; `${` is not.
- **The dogfooding test counts the page.** A six-digit hex color in
  `page.tsx` raises `hexColorsInTsx`, and a `style={{` raises
  `inlineStyleObjects`; either fails `capability-matrix.test.js`. Use a named
  color or a token in examples (`darken(palette(primary.main), 10%)`, not
  `darken(#336699, 10%)`).
- **The matrix cites the page.** New prose can add the page to a row's cited
  files: "uxdsl build" in the text, for one, can put the page among the three
  files of the `build` row. Run `npm run generate:capabilities` and commit the
  diff with the page.
- **JSX text.** Braces in prose need `{'{'}` and `{'}'}`, and `&` needs
  `&amp;`, as lines 28 and 113 do. Code inside a template literal needs
  neither.
- **Overflow at 390 px.** A new table goes inside `doc-section__table-wrap`
  and code inside `<pre>`, which scroll by themselves; the walk fails any
  horizontal page scroll.
- **MIG-B9-20 edits the page first.** Rebase onto `feat/beta9` after it
  merges, and find the passages by their text, not by line.
- **Do not hand-write a list of codes.** The errors table is derived from the
  catalog; the prose names only the codes C1 needs.
- Stop rule: if an example the section needs cannot compile because of a
  pipeline defect, record it in §15 for the story that owns that code
  (MIG-B9-26 for `compile-sass.ts` and `protect.ts`), and do not weaken the
  example or edit `packages/uxdsl`. If the page cannot be made true without a
  pipeline change, leave that passage as it is, record it, and ask the owner.
