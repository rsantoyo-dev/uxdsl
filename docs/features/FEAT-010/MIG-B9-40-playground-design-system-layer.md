## 1. Goal

One component per concept, each styled only with UXDSL roles and tokens in
its own `.uxdsl` compiled as a CSS Module, used by the home page and every
documentation page alike. Every page-specific button, input, code frame,
card and heading is deleted.

## 5. Contract

- **L1 — The module build.** `uxdsl.config.cjs` declares `builds`: the global
  entry (generated by `generate-entry`, carrying the theme marker and the
  page layout files) plus one entry per `src/**/*.module.uxdsl`, computed with
  a glob at config load time, each writing `<name>.generated.module.css` next
  to its source. The generated `.css` files are gitignored and produced by
  `uxdsl:build`/`uxdsl:watch` before Next runs. `watch` lists the module
  sources so a new module is compiled on the next rebuild.
- **L2 — One component per concept**, under `src/components/ds/`, each a
  `.tsx` plus a `.module.uxdsl`, styled only with roles and tokens:
  - `Button` — `@ds-button(<role> [tone] [size])` from props `role`, `tone`,
    `size`; renders `<button>` or `<a>`; every clickable control of the site
    uses it (19 files today).
  - `Field` — `<input>`, `<textarea>`, `<select>` with `@ds-input(<role> …)`,
    a native `<label>`, optional help and error text wired with
    `aria-describedby`; every form control uses it (12 + 8 files today).
  - `Surface` — `@ds-surface(<role> [tone] [size])`; `Card` and `Panel` are
    its two named presets, not separate components; every container uses it.
  - `CodeBlock` — the only way code is shown: one highlighter, one frame,
    scroll inside, light and dark, a "you write / you get" pair mode (25 own
    `<pre>` today).
  - `Section`, `PageTitle`, `Text` — page structure and text through
    `@ds-typo(<role>)` only; `Text` takes a `role` prop (`p`, `small`,
    `caption`, …) and never a font size.
- **L3 — Nothing hand-written in the layer.** The layer's `.module.uxdsl`
  files contain no literal `font-size`, no `var(--uxdsl__…)`, no pixel
  padding/margin/gap/border/radius/shadow, no color literal, no `@media`;
  layout properties (`display`, `grid-template-columns`, `flex`, `gap` with
  `density()`) are allowed. MIG-B9-43 turns this into the enforced check; this
  story meets it for the layer.
- **L4 — Pages use the layer.** Every page and documentation component
  imports from `components/ds`; the absorbed files are deleted:
  `InteractiveDemoContainer`, `PageToolbar`'s own buttons, the demo
  components' own `<button>`/`<input>`/`<pre>`, `DocumentationSection`
  (`Section`), `PageTitle.tsx` (replaced), `CodeBlock.tsx` (replaced). The
  deletion list is produced by the grep of §7 and recorded in §14.
- **L5 — The site looks the same**, except for differences declared in
  advance: `compare.js --noise` between the §4 baseline and the after
  snapshot reports only entries listed in the PR under "intended" (expected:
  code frames unified to one style; buttons unified to the roles' exact
  values where a page had drifted). The walk passes (no console errors, no
  unresolved `var()`, focus visible, no overflow, contrast page equal to Node).
- **L6 — Capabilities stay live.** `npm run generate:capabilities` records no
  gap: the Button and Input demos still render through the real engine (the
  layer's components are themselves live examples of the directives).
- **L7 — Counts move.** Components under `src/components` drop from 55 toward
  the target (about a third); the §2 counts of own `<button>`, `<input>`,
  `<textarea>`, `<pre>` outside `components/ds` are 0.

Must stay byte-identical: the package; `src/app/uxdsl.css`'s theme block.

## 7. Approach and traps

- Inventory first: `grep -rln "<button\|<input\|<textarea\|<pre" src --include='*.tsx' --include='*.mdx'`
  and the `.uxdsl` greps of plan §7.1; paste the lists in the PR and tick
  them off.
- Build the layer in isolation (a hidden `/dev/ds` route that renders every
  component in every role) before switching pages; snapshot it.
- Switch pages one route at a time; snapshot and compare after each; commit
  after each route.
- `Field`'s invalid state follows MIG-B9-36 (`:user-invalid`); its focus
  follows the role's `focus` state; links and buttons get MIG-B9-34's ring.
- The CSS Modules class names are hashed by Next; the snapshot compares
  computed styles by element path, not by class, so the switch is comparable.
- Stop rule: a difference `compare.js` reports that is not in the intended
  list is a regression; fix it or revert that route.
