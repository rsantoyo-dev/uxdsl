## 1. Goal

Running `scripts/codemod-canonical-grammar.js` a second time changes nothing,
and a test pins it. Today the codemod renames
`--uxdsl__typography__h1-font-size` to `--uxdsl__typography__h1-font-font-size`
on a second run, and on a first run over sources that already use the
canonical names, so a project that follows the release notes, which prescribe
it twice, corrupts its own references. After the change a canonical name is
left as it is, and every former name that cannot also be read as a canonical
one is still renamed as it is today.

## 5. Contract

The codemod's public entry is its command line,
`node scripts/codemod-canonical-grammar.js [--write] [--theme <file>] <paths…>`,
run as a subprocess. Where §15's open questions leave a choice, the contract
assumes the option stated there.

- **C1 — A second run is a no-op.** For any files and any `--theme`, once
  `… --write [--theme <file>] <paths…>` has run, the same command run again:
  - writes no file: every file's bytes and modification time are unchanged;
  - exits 0, and its last line starts with `0 file(s) rewritten`;
  - run without `--write`, exits 0 and its last line starts with
    `0 file(s) would change`.

  The `unresolved:` lines (an ambiguous Palette split, `densities(…)`, and
  C4's names under Q1 (b)) are reports, not changes; a second run prints them again. C1 holds
  in every file type the codemod walks (`.uxdsl`, `.css`, `.scss`, `.ts`,
  `.tsx`, `.js`, `.jsx`, `.mdx`, `.md`, `.json`).
- **C2 — A canonical typography variable is never rewritten.** A name
  `--uxdsl__typography__<role>-<property>`, where `<property>` is one of the
  ten names the engine gives typography variables (`TYPOGRAPHY_PROPERTIES`:
  `font-family`, `font-size`, `line-height`, `font-weight`, `letter-spacing`,
  `text-transform`, `text-decoration`, `font-style`, `margin-block-start`,
  `margin-block-end`), is left byte for byte, by the first run as by every
  later one. On BASE six of the ten are rewritten (§4, part 1).
- **C3 — Every former name is still renamed.**
  `--uxdsl__typography__<role>-<former>`, where `<former>` is `size`, `line`,
  `weight`, `spacing`, `transform`, `decoration` or `style` and is not
  followed by a word character or `-`, becomes
  `--uxdsl__typography__<role>-<property>` (`size` → `font-size`, `line` →
  `line-height`, `weight` → `font-weight`, `spacing` → `letter-spacing`,
  `transform` → `text-transform`, `decoration` → `text-decoration`, `style`
  → `font-style`), counted under `typography variable suffixes ×n`, as on
  BASE. A name that only contains a former suffix inside it, such as
  `--uxdsl__typography__h1-size-sm` or `--uxdsl__typography__h1-size_x`, is
  left, as on BASE.

  The one exception is a name C2 keeps. A former name reads exactly like a
  canonical one when its role ends in `-font` and its suffix is `size`,
  `weight` or `style`; when its role ends in `-letter` and its suffix is
  `spacing`; or when its role ends in `-text` and its suffix is `transform`
  or `decoration`. For example, role `body-text`'s former
  `--uxdsl__typography__body-text-transform` is also role `body`'s canonical
  `text-transform`. Such a name is left as it is (§15, Q1). BASE renames it:
  on `f855765`, with a theme defining `body-text` and `lead-font`,
  `body-text-transform` became `body-text-text-transform` and
  `lead-font-weight` became `lead-font-font-weight`.
- **C4 — Under §15's Q1 (b) only: the names a theme role makes ambiguous
  are reported.** Under Q1 (a), which the contract assumes until the owner
  answers, such a name is left by C3's exception with no report, and C4
  does not apply. Under (b): a name that C2 keeps, and that would
  also be the former name of a typography role the effective theme defines
  (the packaged base merged with `--theme`; a role named `<x>-font`,
  `<x>-letter` or `<x>-text`), is printed under its file as one
  `unresolved:` line per occurrence, naming the variable and that role, the
  way an ambiguous Palette split is reported. The file counts among those
  "with findings" and is not changed. A name whose former reading names no
  role of the effective theme is not reported. Without `--theme` the
  effective theme is the packaged base, which has no such role.
- **C5 — Nothing else changes**, against BASE:
  - every other rewrite (`rounded()`, `elevation()`, `radius(full)`, dashed
    `palette()`/`color()`, directive arguments) and the `densities(…)`

## 7. Approach and traps

Non-normative.

- **The shape of the fix.** Match the whole variable name and decide on the
  name, instead of letting a lazy head find a suffix inside it:
  `/--uxdsl__typography__([a-z0-9-]+)(?![\w-])/g`, then:
  - a name that ends in `-<property>` for one of the ten canonical names is
    returned as it is (C2), with C4's report, under Q1 (b), when its former reading names a
    role in `typography_details` of the theme the codemod already resolves
    (line 54) for its Palette split;
  - otherwise `^(.+)-(size|line|weight|spacing|transform|decoration|style)$`
    is renamed through the existing `TYPOGRAPHY_SUFFIXES` map (C3).

  The `(?![\w-])` keeps BASE's end condition (`\b(?!-)`): a name followed by
  `_`, a letter, a digit or `-` is not rewritten, and backtracking cannot
  shorten the name into one that is. `scripts/codemod-namespace.js` decides
  on whole tokens the same way.
- **A prototype, measured on `f855765`.** The rule above, applied to a copy
  of the codemod in a scratch directory (16 lines added, 1 removed; the copy
  never entered the worktree), gave:
  - §4's reproduction: part (1) left the ten canonical names and renamed the
    seven former ones on the first run, and the second run printed
    `0 file(s) rewritten (0 with findings).`; part (2)'s first run rewrote
    14 files, the second printed `0 file(s) rewritten (2 with findings).`
    (the two `densities(…)` reports), `diff -rq exit=0`, 0 lines changed;
  - T8's guard against BASE: 830 lines differ between BASE's first run and
    the prototype's, and every one holds `uxdsl__typography__`; the guard's
    control (BASE with its Palette rewrite turned off) shows 18 other lines;

    and `lead-font-weight` were left and reported once each, in both runs,
    and `body-text-size` was renamed to `body-text-font-size`.

  One run over a copy of the playground's `src` took 0.10 s of wall time, at
  a load average of 8.86, on a machine shared with MIG-B9-20's workflow:
  indicative only.
