## What changes for you

Copied from the CHANGELOG's section `0.5.0-beta.9`:

- One package: `npm i -D uxdsl` replaces `postcss-uxdsl`, `uxdsl-core`,
  `uxdsl-cli`, `vite-plugin-uxdsl` and `uxdsl-webpack-loader`. Imports move to
  `uxdsl`, `uxdsl/postcss`, `uxdsl/vite`, `uxdsl/webpack`, `uxdsl/runtime` and
  `uxdsl/theme`, and it needs Node 20.19 or later.
- `.uxdsl` files compile with real Dart Sass: variables, maps, mixins,
  functions, `@use` and control rules behave as Sass defines them, and the
  compiled CSS takes Dart Sass's formatting.
- The theme is written only where `@uxdsl theme;` appears: put it once in your
  global stylesheet. The `includeTheme` option and the `--include-theme` flags
  are gone.
- The theme file is `uxdsl.theme.json` or `uxdsl.theme.js`/`.cjs` and exports
  the theme itself; `references` moves to `uxdsl.config.cjs`, and
  `uxdsl watch` becomes `uxdsl build --watch`.
- One spelling per construct: `palette(family.variant)`,
  `color(family.shade)`, `@ds-button(role tone size)`. The shipped codemod
  rewrites the old spellings, and a misspelled function name is an error that
  suggests the right one.
- `@media (--lg) { … }` applies a block from a theme breakpoint up and moves
  with the theme.
- In the browser, `applyTheme` and the rest of `uxdsl/runtime`'s theme API
  replace the per-token setters.
- Some colors, focus rings and disabled states of the base theme change: read
  the `Visual changes` tables before upgrading.

| **Where the theme goes** | Only at `@uxdsl theme;`, written once in the global stylesheet; `includeTheme`, `--include-theme` and `--no-include-theme` are removed. A build that references tokens and emits no theme warns `UXD_THEME_MARKER`. |
| **Next.js without the CLI** | `'uxdsl/postcss': {}` in `postcss.config.js` plus `@uxdsl theme;` once in the global stylesheet. | **Grammar** | One spelling: `palette(family.variant)`, `color(family.shade)` (dashed forms are errors); one argument per preset function; directives `@ds-x(role [tone] [size] [radius(k)] [shadow(k)])`. `rounded()`, `elevation()`, `densities()`, `radius(full)`, `@theme { … }` blocks and the flat `typography` family are removed, each with an error naming the replacement. A near-miss name (`palete()`) is `UXD_FUNCTION_UNKNOWN` with a suggestion; a missing numeric key suggests its neighbours. `scripts/codemod-canonical-grammar.js` (shipped) rewrites the old spellings in one run. |
| **Breakpoint blocks** | `@media (--lg) { … }` compiles to the theme's query for `lg` on both paths; an unknown `(--name)` is `UXD_BREAKPOINT_UNKNOWN`, a project `@custom-media` of a breakpoint name warns `UXD_BREAKPOINT_SHADOWED`. |
| **No silent output** | Nested breakpoint functions, responsive values in `@keyframes`, empty or orphan breakpoint groups, a Sass construct reaching `uxdsl/postcss` alone, and another file's `@function` Dart Sass leaves as written under a `@use` entry each fail or warn with a located `UXD_*` code. 108 codes in `DIAGNOSTIC_CATALOG`. |
| **Build = runtime** | The theme CSS the build emits and the one `generateThemeCss`/`applyTheme` emit are byte-identical. Token functions are valid in every theme family; `tone(main\|dark\|contrast)` in Button/Input values. |
| **Runtime** | One API: `applyTheme`, `getAppliedTheme`, `resetTheme`, `subscribeTheme`, `loadPersistedTheme` (`uxdsl/runtime`; no PostCSS inside: 102,954 bytes minified, 30 modules (gate check `I-6`)). The per-token setters are removed. |
| **Base theme** | Passes its own contrast gate (0 failing, 111 excepted by three pattern records). `warning` re-chosen; two dark-mode values; the palette references `colors`; Buttons gain `focusvisible` and `disabled`; `hover`/`active` skip disabled controls; `space(0)`, `border(0)`. **Visual changes**: see the CHANGELOG tables. |
| **Typography variables** | Named after their CSS property (`--uxdsl__typography__h1-font-size`, `-line-height`, `-font-weight`, `-letter-spacing`, …). |
| **Fonts** | The Google Fonts `@import` is placed first, so browsers actually load it (beta.6 defect; already in `0.5.0-beta.8`, new for a beta.6 project). |
| **A wrapper of `uxdsl/postcss`** | The plugin object has `prepare`, not `Once`: a project plugin that called its `Once` itself calls `prepare(result)` and forwards `Once` and `OnceExit` (step 7 below). |
| **Editor / agents** | Typed config from `init`; the agent guide ships at `node_modules/uxdsl/docs/agent-guide.md` (both already in `0.5.0-beta.8`; new for a beta.6 project). |

## From 0.5.0-beta.8 to 0.5.0-beta.9

For a project on the five former packages (`0.5.0-beta.8` or `0.5.0-beta.6`).
`uxdsl` needs Node 20.19 or later.

1. Replace the packages:

   ```bash
   npm uninstall postcss-uxdsl uxdsl-cli uxdsl-core vite-plugin-uxdsl uxdsl-webpack-loader
   npm i -D uxdsl
   npm i -D postcss   # where .npmrc sets legacy-peer-deps=true, npm installs no peer
   ```

2. Rename the theme file: `uxdsl.theme.config.*` → `uxdsl.theme.json`,
   `uxdsl.theme.js` or `uxdsl.theme.cjs`, exporting the theme itself, not
   `{ theme, references }`. `references` moves to `uxdsl.config.cjs`, and
   anything that imported the old file (a `postcss.config.mjs`, say) imports
   the theme from the new one and `references` from `uxdsl.config.cjs`. A
   `theme`, `breakpoints` or `includeTheme` key in `uxdsl.config.cjs`, or in
   one of its `builds`, is an error: remove it.
3. Rewrite the removed spellings, once, over your sources and your theme. Give
   the codemod your theme file, and list the theme module it loads when that
   module is another `.js`/`.cjs` file (a project that keeps its theme in
   `uxdsl.config.js` lists that file):

   ```bash
   # report what would change, then rewrite
   node node_modules/uxdsl/scripts/codemod-canonical-grammar.js --theme uxdsl.theme.cjs src uxdsl.theme.cjs
   node node_modules/uxdsl/scripts/codemod-canonical-grammar.js --write --theme uxdsl.theme.cjs src uxdsl.theme.cjs
   ```

   A second preview reports nothing to change. Without a theme file (the
   zero-config default `init` creates), leave out `--theme …` and the theme
   path (`… --write src`); with `uxdsl.theme.json`, name that file in both
   places.
4. Move any `@theme { … }` block into the theme file (`density-<k>` under
   `densities`, `radius-<k>` under `radii`, …): `0.5.0-beta.8` compiled it,
   this release refuses it as `UXD_THEME_BLOCK_REMOVED` naming the family,
   and the codemod leaves it as written.
5. Write `@uxdsl theme;` once, at the top level of the one global stylesheet
   (after its `@charset`, comments and `@use`/`@import` rules), and nowhere
   else: the theme is emitted only there. With Next.js and the PostCSS plugin
   alone, `postcss.config.js` lists `'uxdsl/postcss': {}`; an `includeTheme`
   option is ignored with a `UXD_OPTION_REMOVED` warning, so remove it. In a
   `builds` project, that stylesheet is the entry whose build had
   `includeTheme: true`; the other entries, and any stylesheet the PostCSS
   plugin compiles, leave it out. If `uxdsl generate-entry` wrote your entry,
   do not edit it: run `npx uxdsl generate-entry` again. It writes
   `uxdsl-theme.uxdsl`, loads it first and moves the entry from `@import` to
   `@use`, so each file becomes its own Sass module: a file that reads
   another file's `$variable`, mixin or placeholder then fails (read its
   warning, and `migration.md`'s "Regenerate the entry").
6. Scripts: `uxdsl watch` becomes `uxdsl build --watch`.
7. Imports: `postcss-uxdsl` → `uxdsl/postcss`; `postcss-uxdsl/ds-runtime` →
   `uxdsl/runtime` (`applyTheme` and the rest of the browser API) or
   `uxdsl/theme` (`generateThemeCss`, `resolveTheme`, `checkThemeContrast`);
   `uxdsl-core` → `uxdsl`; `vite-plugin-uxdsl` → `uxdsl/vite`;
   `uxdsl-webpack-loader` → `uxdsl/webpack`; `import('postcss-uxdsl/config')` in
   the config's `@type` → `import('uxdsl/config')`. Replace every `updatePalette`,
   `updateSpacing`, … call with one `applyTheme` patch. A plugin of your own
   that wraps `uxdsl/postcss` and calls its `Once` itself takes the listeners
   from `prepare` instead:

   ```js
   const uxdsl = require('uxdsl/postcss');
   module.exports = (options) => {
     const plugin = uxdsl(options);
     return {
       postcssPlugin: 'my-uxdsl-wrapper',
       prepare(result) {
         const listeners = plugin.prepare(result);
         return {
           Once: (root, helpers) => listeners.Once(root, helpers),
           OnceExit: (root, helpers) => listeners.OnceExit(root, helpers),
         };
       },
     };
   };
   module.exports.postcss = true;
   ```

8. Rebuild (`uxdsl build`, then your application's build) and compare the
   output with the CHANGELOG's `Visual changes` tables.

`packages/uxdsl/docs/migration.md` has the detail: "To 1.0: one package,
`uxdsl`", "beta.9 — Sass inside compile()", "beta.9 — the theme is emitted
only at `@uxdsl theme;`" and "beta.9 — breakpoint media queries: `@media
(--<breakpoint>)`". "To 1.0"'s first paragraph ("the compiled CSS does not
change", "the same flags", the same effective theme before and after)
describes the package rename alone: from `0.5.0-beta.8` the compiled CSS, the
effective theme `uxdsl theme` prints and the CLI's flags change, as above.

## Known limitations

1. **The playground site is half-migrated.** Its new information
   architecture, home page and documentation pages are in, and no page
   overflows horizontally at any tested width (a walk check pins it); CSS
   Modules per component and the remaining dark-mode polish are FEAT-010's
   wave 4, in `0.5.0-beta.10`. The npm package is not affected.
2. **The markdown documentation is accurate but not yet rewritten** to the
   1.0 architecture (root README, AGENTS.md and CONTRIBUTING, the migration
   guide in English): wave 5, in `0.5.0-beta.10`.
3. **The VS Code extension is not published** (packaging: MIG-B9-55).
4. **Watch.** An output file was once observed empty while a rebuild was
   writing it (the atomic-replace test, on Dependabot's PR #84), and
   webpack's older loader watch tests see an extra build: MIG-B9-06, in
   `0.5.0-beta.10` (decisions 28 and 40 of 2026-11-15, 48 of 2026-11-23).
5. **Windows.** One save reaches `build --watch` as two `change` events on
   win32, so `test/cli/watch-mode.test.js` is outside the Windows CI gate
   (MIG-B9-28's G4, decision 29; MIG-B9-06); a file Dart Sass loads itself
   through `pkg:` is not spelled in its on-disk case on win32 (MIG-B9-102),
   and `build --watch` does not retry a rename onto an output file a reader
   holds open (MIG-B9-103). `verify:1.0`, the parity check and the consumer
   fixtures are not run on Windows (decision 16 of 2026-11-10; MIG-B9-66).
6. **Module isolation warnings.** Their edge cases are MIG-B9-99's
   (MIG-B9-17's follow-up, decision 39 of 2026-11-23).
7. **The codemod** rewrites `${…}` after a function argument in a directive
   only in half (`@ds-surface(contained, radius(2), ${r})` gives
   `@ds-surface(contained radius(2), ${r})`), and leaves the other directives
   its balanced pattern does not match (MIG-B9-18's F11, decisions 55 and 56;
   MIG-B9-60).
8. **The playground's visual comparison** (`fixtures/playground-browser/
   snapshot.js`) runs with `--no-interactions`: its interactions time out
   (MIG-B9-44, decision 12 of 2026-11-09).
9. **`applyTheme` and `generateThemeCss` run the theme engines more than once
   per call** (MIG-B9-24's follow-up 3, decision 53 of 2026-11-23); a
   compilation runs them once.
10. **A CSS-wide keyword as a theme token value** (`inherit`, as Press
    Craftor's `emphasis` role uses) compiles without a word (MIG-B9-37, moved
    to `0.5.0-beta.10`).
11. **Breakpoint blocks.** A `@custom-media` defined in another file is not
    seen with `uxdsl/postcss` alone, and the breakpoint messages under a
    project `@custom-media` (MIG-B9-68); `(--<breakpoint>)` in an `@import`
    media list is left as written (MIG-B9-69); a responsive value in a
    literal `@media` nested in a rule, with `uxdsl/postcss` alone
    (MIG-B9-70).
12. **Timing.** `UX-10` now measures the fastest of five interleaved rounds
    of 1600 and 3200 blocks (at 400 and 800, the theme's own declarations hid
    work quadratic in the declarations);
    the near-linear timing test of reference validation in the package suite
    is still load-sensitive (MIG-B9-101).
13. Scoped palettes do not reach the composites (Press Craftor keeps its own
    PostCSS step for them), and roles and typography have no `extends`
    (MIG-B9-31 to 33, moved).
14. Viewport breakpoints only; no container queries, no fluid `clamp()`
    scales, no DTCG. Not promised before 1.0.
15. **The CLI's `[uxdsl] built … (N bytes)`** counts characters, not bytes:
    a file with multi-byte characters is a few bytes larger on disk
    (MIG-B9-38, moved to `0.5.0-beta.10`).
16. **A wrapper of `uxdsl/postcss` that calls `Once` itself** breaks (the
    table's row, step 7); a compatibility `Once` on the plugin object is a
    `0.5.0-beta.10` follow-up (below).
