# UXDSL 0.5.0-beta.6 — release record (prepublish)

**Status: not published.** This record exists so the owner can decide, with
everything in one place. The packages still carry `0.5.0-beta.5`; the version
bump happens as part of publishing, which is explicitly out of this work's
scope. Nothing below claims a check that was not run, and every check that is
somebody else's to run is named as such.

This release closes [FEAT-008](../features/FEAT-008/README.md), the beta.6
reliability plan, built from an external audit of beta.5 ("Auditoría UXDSL
0.5.0-beta.5", Press Craftor, 2026-09-18) and its verification against `main`,
which confirmed the findings and added eight more.

## What changed

Twenty stories. The short version: beta.5 had one language with three
compilers, errors without positions, flags that did nothing, a theme whose
defaults lived in the playground rather than the library, and no way to see a
source map or apply a theme at run time. beta.6 addresses each.

| Area | What it means for a consumer |
| --- | --- |
| One pipeline | The CLI, `compile()`, Vite and Webpack share one compiler. A missing `@import` fails with a located error instead of reaching the browser; an import cycle names the file chain. |
| Diagnostics | Every error carries a `UXD_*` code and a file:line:column. Directives that used to pass through as text — misspelled, at the root, inside `@media` — now fail. An unknown breakpoint function is an error, not silent output. |
| Flags | Unknown flags and unknown families fail with a suggestion. `--include-theme=false` and `--strict-theme=...` do what they say. |
| Theme | The reviewed base JSON *is* the library default, shipped in the package. A partial override is visible (`theme --diff`) and checkable (`theme --contrast`). |
| Typography | `@ds-typo` emits one declaration per field the theme defines, with no invented fallbacks — smaller output and no accidental reset. |
| Source maps | `--sourcemap` / `--sourcemap=inline`, and `sourceMap` in config. Devtools point at the `.uxdsl`. |
| Runtime | `applyTheme(json)` applies the same theme JSON a build compiles, synchronously, and refuses changes compiled CSS could not follow. |
| Types | `UxdslTheme`, `UxdslConfig` and friends are exported; `defineConfig` and a generated JSON Schema catch typos in the editor. |
| Performance | Reference validation went from quadratic to near-linear: 24,000 lines from 63.3 s to 0.79 s on the machine recorded in that story. |
| Packaging | Five packages with a `files` field, no tests or images shipped, budgets enforced by `release.js`. |

Read the [migration guide](../../packages/postcss-uxdsl/docs/migration.md) and
the [changelog](../../packages/postcss-uxdsl/CHANGELOG.md) before upgrading.

## Provenance (D-1)

The theme a build compiles is the packaged base JSON plus the project's
override, merged key by key — `postcss-uxdsl/theme/base.json` is
`DEFAULT_THEME`, not a playground convenience file. The merge is unchanged by
design: nothing is derived, and `build` stays quiet. What changed is that it is
now *visible*, because the silent half is where the surprises were:

| Question | Command |
| --- | --- |
| Which values are mine and which are inherited? | `uxdsl theme --diff` |
| Which of my families are only partly mine? | the stderr summary that command now prints |
| Do the resulting pairs meet WCAG? | `uxdsl theme --contrast` |

### Browser — run, passing, separate job

`npm run verify:cssmodules-build`, with Chrome declared through
`UXDSL_CHROME_PATH` (default `/Applications/Google Chrome.app/...`). Covers
computed padding/radius/border across 12 breakpoint boundaries in both modes,
plus 20 checks of the runtime theme API against the **packaged** runtime:
adopting a server-rendered style tag without duplicating it, a value patch
repainting, a structural patch refused without moving the pixels,
`prefers-color-scheme` and explicit `data-theme`, hover, keyboard focus,
`::placeholder`, `:invalid`, and font requests intercepted locally.

### External — **pending, owner or the Press Craftor team**

Not run here, and not runnable here. Required before approval:

- zero UXDSL warnings in that project's build;
- a CSS diff against beta.5 where every change maps to a documented fix or
  visual change — selectors, `!important`, `@ds-typo` output and defaults all
  changed in this release, so the diff will be large and each cluster needs to
  be attributable;
- `next build` passing;
- a day of `uxdsl watch` in development with no forced restarts.

The tarballs validated must be the ones published. Any change after that
validation invalidates it for the affected checks.

### Postpublish — **pending, after the owner publishes**

Per D-6, `latest` follows the most recent beta: after publishing, both `latest`
and `beta` must point at `0.5.0-beta.6` for all five packages.
`scripts/release.js` verifies this, and it has never run against the real
registry — its first real execution will be this release.

## Known limitations

These are real and disclosed, not oversights:

1. **The packaged base theme does not pass its own contrast gate.** With the
   shipped exceptions applied, `checkThemeContrast` reports 156 failing pairs.
   These are three engine/architecture gaps MIG-B6-29 phase 3 left open and
   documented, not colour choices — see that story's evidence for which. The
   gate runs, reports honestly and is wired into `uxdsl theme --contrast`; a
   zero-config user will see inherited failures on a first run, which the
   READMEs and migration guide say plainly.
2. **`applyTheme` is not a compiler.** It applies values. A patch that changes
   what a directive would emit — a typography field added or removed, a state
   introduced, a Button's Surface changed, a threshold moved — is refused with
   `UXD_THEME_STRUCTURE` and an instruction to rebuild.
3. **Three legacy runtime capabilities have no `applyTheme` equivalent**:
   per-element scope, moving a breakpoint threshold at run time, and token
   links. The old setters still work and nothing was removed in beta.6.
4. **Vite source maps are not advertised.** The plugin hands Vite a correct
   map, but its fixture shows Vite's CSS pipeline does not carry the `.uxdsl`
   source through to the emitted asset. Webpack's is verified end to end.
5. **`postcss-advanced-variables` stays on `^3`.** `^4`/`^5` break expansion of
   `@mixin` `$var` parameters used as directive arguments, and `5.0.0` also
   changes compiled whitespace. See the CLI README.
6. **The playground app itself was not driven in a browser.** Its production
   build (35/35 pages) and lint cover it; the runtime logic is covered in
   Chrome through the packaged runtime, in a controlled document.
7. **No `LICENSE` file exists in the repository**, while all five package
   READMEs link to one. Carried over from MIG-B6-26; not introduced here.

## Can this gate actually fail?

A gate that cannot go red is decoration, so it was checked rather than assumed,
and the check found a real defect in the gate itself:

- The first version of `fixtures/mig-b6-12-release/run.js` did not `await` its
  asynchronous checks. `fn()` returned a pending Promise, which is truthy, so
  every async check passed no matter what it asserted. This surfaced only
  because reverting MIG-B6-15 left the gate green. Fixed, and the fix is what
  makes the two results below meaningful.
- With MIG-B6-15 reverted (selector splitting), `UX-05` fails:
  `split inside :is()`.
- With MIG-B6-22 reverted (strict flag parsing), `UX-04` fails:
  `nonexistent flag: exited 0`.

The gate also found a real product bug while being written: `uxdsl theme
--contrast | jq` produced truncated JSON, because `process.exit()` discards a
pipe's buffered output. Redirected to a file the same command wrote 302,816
bytes; piped, 65,536, ending mid-string. Fixed by using `process.exitCode`
throughout, with its own regression test.
