# UXDSL 0.5.0-beta.7 — release record (prepublish)

**Status: ready to publish, not published.** The repository already carries
`0.5.0-beta.7` (`packages/uxdsl` and the five shims), so the tarball the gate
verified is the tarball that gets published. Nothing below claims a check that
was not run; every step that is the owner's is named as such.

**What this release is:** the first release of the one package, **`uxdsl`**.
It ships everything on `main` since `0.5.0-beta.6` — FEAT-009's beta.7 stories
and the stability plan's phases 0–5 — plus the dependency replacements and the
first half of phase 6 (the playground site). Unfinished work moves to
`0.5.0-beta.8` (see the end of this record). The plan behind it:
`docs/audits/2026-09-29-auditoria-estabilidad.md` and
`docs/audits/2026-10-07-handoff-stability.md`.

## What changed for a consumer

**This is a breaking beta.** Read the
[CHANGELOG](../../packages/uxdsl/CHANGELOG.md) section `0.5.0-beta.7`
(including every `Visual changes` and `Removed` table) before upgrading.

| Area | What changes |
| --- | --- |
| **One package** | `npm i -D uxdsl` replaces `postcss-uxdsl`, `uxdsl-core`, `uxdsl-cli`, `vite-plugin-uxdsl` and `uxdsl-webpack-loader`. Entries: `uxdsl` (`compile()`), `uxdsl/postcss`, `uxdsl/vite`, `uxdsl/webpack`, `uxdsl/runtime`, `uxdsl/theme`, `uxdsl/language`, `uxdsl/config`, `uxdsl/engine` (tooling, exempt from semver). `postcss` is a peer. Old → new import table in the CHANGELOG ("Package layout"). |
| **Install** | 20 packages, `npm audit` 0 vulnerabilities (beta.6: 38 packages, 4 high). `chokidar` 4 + `picomatch` for watch; the SCSS subset is UXDSL's own (no `postcss@7`). Vite 4–8 accepted. |
| **Theme files** | `uxdsl.theme.json` or `uxdsl.theme.js`/`.cjs` (the `uxdsl.theme.config.*` names are an error naming the new one). One validator: every leaf a non-empty string, no coercion, `null` invalid. |
| **CLI** | `uxdsl build --watch` (the `watch` command is gone), `--version`, per-command `--help`, one `--strict-theme=<families>` (scope required). `init` writes a typed `uxdsl.config.cjs`, scaffolds `src/styles.uxdsl`, and on Next.js keeps Next's default PostCSS plugins. |
| **Next.js without the CLI** | `'uxdsl/postcss': { includeTheme: false }` plus `@uxdsl theme;` once in the global stylesheet. |
| **Grammar** | One spelling: `palette(family.variant)`, `color(family.shade)` (dashed forms are errors); one argument per preset function; directives `@ds-x(role [tone] [size] [radius(k)] [shadow(k)])`. `rounded()`, `elevation()`, `densities()`, `radius(full)`, `@theme { … }` blocks and the flat `typography` family are removed, each with an error naming the replacement. `scripts/codemod-canonical-grammar.js` (shipped) rewrites the old spellings. |
| **No silent output** | Nested breakpoint functions, responsive values in `@keyframes`, empty or orphan breakpoint groups, and every Sass construct outside the subset fail with a located `UXD_*` code; the 110-case SCSS matrix has 0 silent cases. 106 codes in `DIAGNOSTIC_CATALOG`. |
| **Build = runtime** | The theme CSS the build emits and the one `generateThemeCss`/`applyTheme` emit are byte-identical. Token functions are valid in every theme family; `tone(main\|dark\|contrast)` in Button/Input values. |
| **Runtime** | One API: `applyTheme`, `getAppliedTheme`, `resetTheme`, `subscribeTheme`, `loadPersistedTheme` (`uxdsl/runtime`; no PostCSS inside: 95 KB min / 30 KB gz, was 159 / 51). The per-token setters are removed. |
| **Base theme** | Passes its own contrast gate (0 failing, 111 excepted by three pattern records). `warning` re-chosen; two dark-mode values; the palette references `colors`; Buttons gain `focusvisible` and `disabled`; `hover`/`active` skip disabled controls; `space(0)`, `border(0)`. **Visual changes**: see the CHANGELOG tables. |
| **Typography variables** | Named after their CSS property (`--uxdsl__typography__h1-font-size`, `-line-height`, `-font-weight`, `-letter-spacing`, …). |
| **Fonts** | The Google Fonts `@import` is placed first, so browsers actually load it (beta.6 defect). |
| **Editor / agents** | Typed config from `init`; the agent guide ships at `node_modules/uxdsl/docs/agent-guide.md`. |

## Publish steps — the owner's

From a clean checkout of `main` after PR #25 is merged and CI is green:

```bash
npm ci --ignore-scripts
(cd packages/uxdsl && npm ci)
npm test
npm run verify:1.0
node scripts/release.js --version 0.5.0-beta.7 --tag latest --otp <code>
npm dist-tag add uxdsl@0.5.0-beta.7 beta --otp <code>
npm view uxdsl dist-tags            # latest and beta → 0.5.0-beta.7
```

`release.js` builds, regenerates the language artifacts, checks the exact
tarball (300 KB budget, every declared entry point present), publishes it,
builds the VS Code VSIX (not published) and then checks that `latest` and
`beta` both point at the version, printing the `npm dist-tag add` command for
any that does not. `uxdsl` is a new name on npm: this publish creates it.

### The five former names

Recommended for this beta: **deprecate them, do not publish the shims yet.**
`npm deprecate` adds a warning on install without changing what any existing
project resolves, so `story-radar` keeps building on `0.5.0-beta.6` until it is
moved deliberately:

```bash
node -e "const m=require('./packages/_deprecated/deprecations.json'); for (const [n,t] of Object.entries(m)) console.log(n + '\t' + t)" |
while IFS="$(printf '\t')" read -r name message; do
  npm deprecate "$name@*" "$message" --otp <code>
done
```

Optional, only if you want `npm i postcss-uxdsl` to land on `uxdsl` now: the
shims under `packages/_deprecated/` are at `0.5.0-beta.7` and depend on exactly
`uxdsl@0.5.0-beta.7`, so publish them only after `uxdsl` resolves from the
registry (`cd packages/_deprecated/<name> && npm publish --access public --tag latest`).
Publishing them moves every project that installs those names with a `^` range
or the `beta`/`latest` tag onto the new package, with its breaking changes.

### Afterwards

- Bump `packages/uxdsl` to `0.5.0-beta.8-dev` right away, so a local tarball

- VS Code: publish the VSIX that `release.js` leaves in `packages/uxdsl-vscode`

## Moving `story-radar` (or any beta.6 project)

```bash
npm uninstall postcss-uxdsl uxdsl-cli uxdsl-core vite-plugin-uxdsl uxdsl-webpack-loader
npm i -D uxdsl
# report what would change, then rewrite (paths: your .uxdsl/.css/.json sources)
node node_modules/uxdsl/scripts/codemod-canonical-grammar.js --theme uxdsl.theme.json src
node node_modules/uxdsl/scripts/codemod-canonical-grammar.js --write --theme uxdsl.theme.json src
```

Then: rename `uxdsl.theme.config.*` to `uxdsl.theme.*` (a theme file exports
the bare theme; `references` moves to `uxdsl.config.cjs`); replace the
`uxdsl watch` script with `uxdsl build --watch`; change imports from
`postcss-uxdsl/ds-runtime` to `uxdsl/runtime` / `uxdsl/theme`; replace any
`updatePalette`/`updateSpacing`/… call with one `applyTheme` patch; run the
grammar codemod over the `.uxdsl` files; rebuild and compare.

## Known limitations

1. **The playground site is half-migrated.** Its new information architecture,
   home page and documentation pages are in, and no page overflows
   horizontally at any tested width (a walk check pins it); CSS Modules per
   component and the remaining dark-mode polish are beta.8. The npm package
   is not affected — the playground is the documentation site.
2. **The markdown documentation is accurate but not yet rewritten** to the
   1.0 architecture (root README ≤120 lines, AGENTS.md ≤600 + CONTRIBUTING,
   migration guide in English). beta.8.
3. **The VS Code extension is not published** (packaging prepared in beta.8).
4. "Did you mean" for numeric keys suggests the first key at edit distance 1
   (`color(gray.350)` → `50`), not the numerically nearest.
5. Viewport breakpoints only; no container queries, no fluid `clamp()`
   scales, no DTCG. Not promised before 1.0.
