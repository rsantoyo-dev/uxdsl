# UXDSL 0.5.0-beta.3

Published from main commit `796d309936a6e809fecc96770e92a950299680f8`, under npm `latest` at the owner's explicit request. Both `latest` and `beta` point to this prerelease, matching how `0.5.0-beta.1` and `0.5.0-beta.2` were published. It remains beta software; a dist-tag does not change its maturity.

All five distribution packages use version `0.5.0-beta.3`: `postcss-uxdsl`, `uxdsl-core`, `vite-plugin-uxdsl`, `uxdsl-webpack-loader`, and `uxdsl-cli`.

This release closes [FEAT-004](../features/FEAT-004-beta3-cli-plugin-parity.md), CLI/plugin option parity, based on a real consumer's beta.1→beta.2 migration report:

- `uxdsl build`/`watch` now forward `includeTheme` to the plugin (`--include-theme`/`--no-include-theme`, or `includeTheme` in `uxdsl.config.cjs`) — previously unreachable from the CLI, forcing every CLI build to emit a global `:root` even for a component/CSS-Module entry meant to only consume tokens.
- `theme.breakpoints` (already supported and validated by the plugin) is no longer permanently shadowed by the CLI's own default fallback; config and theme breakpoints now merge onto shared defaults, config winning key-for-key.
- A theme file shaped like a build config, or a theme with an unrecognized top-level family, now warns instead of silently doing nothing.
- New `uxdsl theme` command (`--diff`, `--strict`) prints the resolved effective theme and which values are the project's own versus inherited from `DEFAULT_THEME`.
- `uxdsl.config.cjs` can declare a `builds` array — several entries compiled from one shared theme in a single invocation, written atomically (a failure in one leaves every output untouched).

Read [the migration guide](../../packages/postcss-uxdsl/docs/migration.md) and [changelog](../../packages/postcss-uxdsl/CHANGELOG.md) before upgrading from 0.5.0-beta.2.

Preparation checks: the full engine/core/CLI test suites (57 CLI tests including real chokidar/subprocess watch-mode coverage), the new `plugin-option-parity` structural guard, the `verify-docs-update.js` visual-change guard with its own test coverage, and the `mig-b3-06-release` fixture (5 real tarballs, zero duplicate `:root`/`#uxdsl-bp-meta`, theme-file-only breakpoints reaching a component entry, both negative controls) all passed. `mig-b2-05-release` was re-verified passing unchanged after its tarball-install mechanism was extracted into a shared helper. These checks do not establish complete browser or accessibility coverage.

Published via `node scripts/release.js --version 0.5.0-beta.3 --tag beta` (dependency order: `postcss-uxdsl` → `uxdsl-core` → `vite-plugin-uxdsl` → `uxdsl-webpack-loader` → `uxdsl-cli`), then `npm dist-tag add <pkg>@0.5.0-beta.3 latest` for each package to match the owner's requested dual-tag strategy. Unlike beta.2, this publish succeeded on the first attempt with no OTP/2FA prompt.

Registry verification confirmed both `latest` and `beta` tags at `0.5.0-beta.3` for every package (allowing for npm's normal post-publish indexing delay on both the initial publish and the subsequent `latest` tag additions). A fresh install of `postcss-uxdsl@beta` and `uxdsl-cli@beta` from the real registry into an isolated directory, followed by `uxdsl init`, `uxdsl build`, and `uxdsl theme --diff`, produced valid `--uxdsl__`-namespaced CSS and correct (empty, zero-config) diff output. A second isolated install additionally verified the new `builds` array end to end — a theme entry and a component entry compiled together, only the theme entry defining `:root` — confirming the published tarballs work outside the monorepo.
