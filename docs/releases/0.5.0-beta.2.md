# UXDSL 0.5.0-beta.2

Published from main commit `4ad9a66102ada37a30876a1c06653672d7d8c458`, under npm `latest` at the owner's explicit request. Both `latest` and `beta` point to this prerelease, matching how `0.5.0-beta.1` was published. It remains beta software; a dist-tag does not change its maturity.

All five distribution packages use version `0.5.0-beta.2`: `postcss-uxdsl`, `uxdsl-core`, `vite-plugin-uxdsl`, `uxdsl-webpack-loader`, and `uxdsl-cli`.

This release closes out FEAT-003 (beta.2 smooth-install): `uxdsl.theme.config.*`/`uxdsl.config.*` discovery, the canonical default theme with partial merge, the zero-config `uxdsl init` + `uxdsl:build` flow, and the `--uxdsl__<family>__<key>` namespace rename from FEAT-002. Read [the migration guide](../../packages/postcss-uxdsl/docs/migration.md) and [changelog](../../packages/postcss-uxdsl/CHANGELOG.md) before upgrading from 0.5.0-beta.1 or earlier builds.

Preparation checks: the full engine/core/consumer test suites, the cascade-order comparison fixture, the MIG-B2-05 coordinated-tarball release-gate fixture (build/watch parity, component-scoped tone hooks), and three rounds of watch-mode regression tests against real `chokidar`/CLI subprocesses (stale config/theme reuse, self-triggering on the output file, nested `require` cache invalidation, dynamic `outFile` exclusion, and auto-watching the config file itself) all passed. These checks do not establish complete browser or accessibility coverage.

Published via `node scripts/release.js --version 0.5.0-beta.2 --tag beta` (dependency order: `postcss-uxdsl` → `uxdsl-core` → `vite-plugin-uxdsl` → `uxdsl-webpack-loader` → `uxdsl-cli`), then `npm dist-tag add <pkg>@0.5.0-beta.2 latest` for each package to match the owner's requested dual-tag strategy. Publishing required a Granular Access Token with "Read and write (publish and stage)" permission and temporarily unchecking the npm account's "Require two-factor authentication for write actions" setting, which the owner should re-enable now that the release is complete.

Registry verification confirmed both `latest` and `beta` tags at `0.5.0-beta.2` for every package (allowing for npm's normal post-publish indexing delay on four of the five packages). A fresh install of `postcss-uxdsl@beta` and `uxdsl-cli@beta` from the real registry into an isolated directory, followed by `uxdsl init` and `uxdsl build`, produced a valid `--uxdsl__`-namespaced CSS file, confirming the published tarballs work end to end outside the monorepo.
