# UXDSL 0.5.0-beta.5

Published from main commit `4bcfe051bef883d783c786a2cd6eca35a7c1e173`, under npm `latest` at the owner's explicit request. Both `latest` and `beta` point to this prerelease, matching how every prior `0.5.0-beta.x` was published. It remains beta software; a dist-tag does not change its maturity.

All five distribution packages use version `0.5.0-beta.5`: `postcss-uxdsl`, `uxdsl-core`, `vite-plugin-uxdsl`, `uxdsl-webpack-loader`, and `uxdsl-cli`.

This release closes [FEAT-006](../features/FEAT-006-beta5-scoped-strict-theme.md), based on a real consumer's CI report. Entirely additive — no migration steps needed from beta.4:

- `--strict-theme`/`uxdsl theme --strict` now accept an optional family scope (`--strict-theme=palette,breakpoints`, or `strictTheme: ['palette', 'breakpoints']`). Fixes a real false positive: the bare flag flags any documented partial theme override as "incomplete" — not just in `typography_details`, but in the zero-config `palette` example this project's own README uses. `true`/the bare flag is unchanged.
- `validateAndNormalizeTheme` now also warns about an unrecognized entry name inside `typography_details`/`palette`/`fonts.families` (a typo, not an incomplete override) — and, together with its pre-existing top-level "Unknown theme family" warning, actually prints from a real `uxdsl build`/`watch` for the first time; previously only the playground's theme editor called that function.
- `packages/postcss-uxdsl/README.md` was rewritten with a verified "See it in 60 seconds" tour (responsive values, palette tokens, density, buttons, live theming) replacing an image-only syntax preview.

Read [the migration guide](../../packages/postcss-uxdsl/docs/migration.md) and [changelog](../../packages/postcss-uxdsl/CHANGELOG.md) before upgrading from 0.5.0-beta.4.

Preparation checks: the full engine/core/CLI test suites, the `mig-b5-03-release` fixture (5 real tarballs: the exact reported repro still failing unscoped, passing scoped to `palette`, and the unknown-key warning printing from a real build without blocking it), and every prior release-gate fixture (`verify:beta2` through `verify:beta4`) re-verified passing unchanged, all passed. These checks do not establish complete browser or accessibility coverage.

Published via `node scripts/release.js --version 0.5.0-beta.5 --tag beta` (dependency order: `postcss-uxdsl` → `uxdsl-core` → `vite-plugin-uxdsl` → `uxdsl-webpack-loader` → `uxdsl-cli`), then `npm dist-tag add <pkg>@0.5.0-beta.5 latest` for each package. Like beta.3 and beta.4, this publish succeeded with no OTP/2FA prompt. `release.js` itself changed for this release: it now runs `generate-language-artifacts.js` automatically right after bumping every package's version, closing a recurring drift — `theme-manifest.json`'s `uxdslVersion` had gone stale after both the beta.3 and beta.4 publishes, caught only by a release-gate fixture's own registry check each time. This publish is the first to verify the manifest stayed in sync on its own.

Registry verification confirmed both `latest` and `beta` tags at `0.5.0-beta.5` for every package (allowing for npm's normal post-publish indexing delay on four of the five packages for the initial publish; the `latest` tag addition propagated immediately for all five). A fresh install of `postcss-uxdsl@beta` and `uxdsl-cli@beta` from the real registry into an isolated directory confirmed: the packaged `theme-manifest.json` correctly reports `0.5.0-beta.5` (the manifest-sync fix holding on a real publish, not just in the monorepo), `uxdsl build --strict-theme` passing on zero-config and failing (naming `typography_details`, exit code 1) on the exact reported repro, `uxdsl build --strict-theme=palette` passing the same theme by scoping the check, and the "Unknown theme family" warning printing (without blocking the build) once the scoped build's strict-theme gate stopped short-circuiting past it — confirming the published tarballs work end to end outside the monorepo.
