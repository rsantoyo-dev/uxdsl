## What runs here

`checkThemeContrast(resolveTheme(theme), { exceptions })` from `postcss-uxdsl/ds-runtime`, with the exceptions shipped next to the base theme (`postcss-uxdsl/theme/base.contrast-exceptions.json`) — the same call `uxdsl theme --contrast` makes in a terminal (its real output is on the CLI page). It checks every text, placeholder and border pair the Surface, Button and Input engines define, in light and dark mode, at every configured breakpoint width, against 4.5:1 for text and 3:1 for borders.

It checks the colors a theme resolves to, not a rendered page: it is not an accessibility certification. And today it fails, for this site's themes and for the packaged base: the failures are real, disclosed and tracked (MIG-B6-29, MIG-B7-01), not hidden behind exceptions. That is what the verdict below says.
