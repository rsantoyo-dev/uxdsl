    <h2 className="ds-typo" data-typo="h2">The Power of Semantic Typography</h2>
    <div className="doc-paragraph">
      UXDSL decouples visual style from HTML tags. While you can write standard HTML, the real power comes from the <code>@ds-typo</code> mixin. 
      This allows you to apply the visual properties of a "Heading 1" to <em>any</em> element, while maintaining semantic correctness.
    </div>
    <div className="doc-paragraph">
      Because these mixins are backed by CSS variables, <strong>changing the theme instantly updates every instance</strong> of that typography style across your entire application—spacing, weight, size, and line-height included.
    </div>

    <h3 className="ds-typo" data-typo="h3">Usage Example</h3>
    <div className="code-wrapper">
      <CodeBlock language="css" code={`/* Apply H1 visuals to a div */
.hero-title {
  @ds-typo (h1);
  color: palette(primary-dark);
}

/* Apply Body visuals to a span */
.description {
  @ds-typo (body);
  opacity: 0.8;
}`} />
    </div>

    <h2 className="ds-typo" data-typo="h2">What Prevents “Knockout” Today</h2>
    <div className="doc-paragraph">
      “Knockout” here means: a typography system that is role-driven, fluid, density-aware, auditable, and easy to evolve without regressions.
    </div>
    <div className="table-card">
      <table className="doc-table">
        <thead>
          <tr>
            <th>Gap</th>
            <th>Why it matters</th>
            <th>What to build</th>
          </tr>
        </thead>
        <tbody>
          <tr>
            <td>Missing role abstraction</td>
            <td>Tokens tied to tags can’t express intent like “label”, “kicker”, “eyebrow”, “metric”.</td>
            <td>Add a role layer (e.g. <code>typo_roles</code>) and map roles → details, then apply via <code>@ds-typo(role)</code>.</td>
          </tr>
          <tr>
            <td>No fluid / optical scaling</td>
            <td>Breakpoint steps can feel jumpy; headings may look oversized/undersized between breakpoints.</td>
            <td>Support fluid values (e.g. clamp-based) or a computed scale per viewport, plus optional optical adjustments.</td>
          </tr>
          <tr>
            <td>Typography not density-aware</td>
            <td>Dense UI needs different sizes/line-heights than roomy layouts, even with the same theme.</td>
            <td>Allow density to select a typography preset (or apply density multipliers to size/line).</td>
          </tr>
          <tr>
            <td>Demo lacks introspection tools</td>
            <td>Hard to debug “what resolved where” and why a token looks the way it does.</td>
            <td>Add an inspector: resolved values per breakpoint + inherited-from + final CSS vars.</td>
          </tr>
          <tr>
            <td>Defaults could be stronger</td>
            <td>Most users copy defaults; weak defaults lead to inconsistent apps.</td>
            <td>Ship stronger built-in scales + role presets + accessibility-first recommendations.</td>
          </tr>
        </tbody>
      </table>
    </div>

    <h2 className="ds-typo" data-typo="h2">Customizing Typography</h2>
    <div className="doc-paragraph">
      You can override the default type scale by adding a <code>typography_details</code> section to your <code>uxdsl.theme.json</code> file. 
      This allows you to fine-tune sizes, weights, and line-heights for every semantic tag.
    </div>
    <div className="doc-paragraph">
      The <code>fontSize</code> and <code>lineHeight</code> properties support UXDSL's responsive syntax, allowing you to define scaling from mobile to desktop in a single line.
    </div>
  
    <div className="code-wrapper">
      <CodeBlock language="json" code={`// uxdsl.theme.json
		{
		  "typography_details": {
		    "h1": {
		      "fontSize": "xs(space(7)) md(space(8)) lg(space(9)) xl(space(10))",
		      "fontWeight": "800",
		      "lineHeight": "1.1",
		      "letterSpacing": "-0.03em"
		    },
		    "p": {
		      "fontSize": "xs(space(5))",
		      "lineHeight": "1.6"
		    }
		  }
		}`} />
    </div>

    <h2 className="ds-typo" data-typo="h2">Breakpoint Resolution & Responsive Rules</h2>
    <div className="doc-paragraph">
      UXDSL supports responsive values using the <code>xs()</code> <code>sm()</code> <code>md()</code> <code>lg()</code> <code>xl()</code> syntax.
      When a value is missing at a breakpoint, it inherits from the nearest lower breakpoint that defines it.
    </div>

    <h3 className="ds-typo" data-typo="h3">Nearest-lower-breakpoint inheritance</h3>
    <div className="code-wrapper">
		<CodeBlock language="json" code={`{
		  "typography_details": {
		    "h1": { "fontSize": "xs(space(7)) md(space(8))" }
		  }
		}`} />
	    </div>

    <h3 className="ds-typo" data-typo="h3">Resolution rules (summary)</h3>
    <div className="table-card">
      <table className="doc-table">
        <thead>
          <tr>
            <th>Rule</th>
            <th>What it means</th>
          </tr>
        </thead>
        <tbody>
          <tr>
            <td>Inherit down</td>
            <td>Missing breakpoint values inherit from the nearest lower breakpoint that is defined.</td>
          </tr>
          <tr>
            <td>Prefer explicit</td>
            <td>If a breakpoint is present (e.g. <code>lg(...)</code>), it wins for that breakpoint and above until overridden.</td>
          </tr>
          <tr>
            <td>Same syntax everywhere</td>
            <td>Any string-based typography field can use <code>xs()</code>/<code>md()</code>/… syntax.</td>
          </tr>
        </tbody>
      </table>
    </div>
