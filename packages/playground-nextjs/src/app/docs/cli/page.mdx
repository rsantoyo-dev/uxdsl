## uxdsl build: discovery, `--config`, `--entry`

With no flags, `uxdsl build` finds `uxdsl.config.cjs` in the current directory and the theme file next to it. `--config` names the config file; `--entry` with `--out` compiles one file to one output instead of the config's entry.

## `--include-theme` and `--no-include-theme`

`--include-theme` is the default: the entry also defines every token in `:root`, once. A second entry — a component or CSS-Module stylesheet — passes `--no-include-theme` to emit only its rules, consuming the tokens the first entry already defined. The same `card.uxdsl`, both ways:

## `--sourcemap`

Writes `<outFile>.map` next to the CSS and a `sourceMappingURL` comment, so devtools point at the `.uxdsl` line that produced a rule. `--sourcemap=inline` embeds the map instead.

## `--strict-theme=<families>`

Fails the build, before writing anything, when one of the named families was partly filled from the base theme. This project overrides only `palette.primary.main`, so `--strict-theme=palette` fails; `--strict-theme=breakpoints`, a family it declares completely, passes. A scope is required: the theme model is partial overrides, so an unscoped check flagged the recommended usage as incomplete — the bare flag is refused and says so.

</div>

## uxdsl theme: `--diff`, `--strict-theme`, `--contrast`

`uxdsl theme` prints the effective theme — the same discovery and resolution as `build`, no CSS written, and it works from a theme file alone. `--diff` prints only what your theme file mentions, one row per leaf labeled `project` or `default` (`$schema` is not a leaf), and says on stderr where a family mixes the two. `--strict-theme=<families>` exits non-zero when one of the named families was partly inherited — the same flag and rule as `build`'s. `--contrast` runs the WCAG gate and prints its full JSON report; the Contrast page runs the same function in your browser.

## uxdsl build --watch

`uxdsl build --watch` builds, then rebuilds when a source changes. A broken edit is reported and the last good CSS stays on disk; the next valid save recovers. A session, recorded by the capture script as it edited the file:

## `--help`, `--version`, and what is not a command

Bare `uxdsl` prints the help instead of building; `uxdsl <command> --help` prints that command's options and nothing else (`uxdsl init --help` is where `--multi`, the theme-plus-panels scaffold, is described); `uxdsl --version` prints the one version of the installed `uxdsl` package — the CLI, the compiler and the theme model are one install. An unknown command is one line with a hint — `watch`, which used to be a command, points at `uxdsl build --watch`.
