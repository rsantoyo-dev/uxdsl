## What runs here

`checkThemeContrast(resolveTheme(theme), { exceptions })` from `uxdsl/theme`, with the exceptions shipped next to the base theme (`uxdsl/theme/base.contrast-exceptions.json`) — the same call `uxdsl theme --contrast` makes in a terminal (its real output is on the CLI page). It checks every text, placeholder and border pair the Surface, Button and Input engines define, in light and dark mode, at every configured breakpoint width, against 4.5:1 for text and 3:1 for borders.

It checks the colors a theme resolves to, not a rendered page: it is not an accessibility certification. Since stability phase 5 the packaged base and this site's four themes pass it: zero failing pairs. Passing is not "every pair passed": the pairs the three shipped pattern exceptions cover — the canvas-identity families `surface`, `light` and `dark` used as a tone and drawn on the page itself — are listed below as excepted, with their real ratio and the exception that covers each, and a pattern that covered nothing would fail the verdict.
