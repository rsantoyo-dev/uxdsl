A UXDSL error names a `UXD_*` code, the file, line and column, and shows the line; the message says what exists instead (the configured breakpoints, the available keys, a close name). Nothing falls back silently: an unknown breakpoint, preset, role or reference stops the build. The runtime reports its codes on a result (`applyTheme(...).error.code`) instead of throwing.

## Every code

Read from `DIAGNOSTIC_CATALOG` (`uxdsl/language`), the catalog the compiler itself throws from: a test fails when the compiler can produce a code the catalog does not list, or when a listed code is produced nowhere.
