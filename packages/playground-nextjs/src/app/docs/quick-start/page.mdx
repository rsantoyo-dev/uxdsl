## 1. Install

```bash
npm i -D uxdsl
```

`postcss` (`^8.4.31`) is a peer dependency, which npm 7 and later install for you.

## 2. Scaffold

```bash
npx uxdsl init
```

`init` writes a typed `uxdsl.config.cjs`, `src/styles.uxdsl` (the file you edit) and `src/uxdsl-entry.uxdsl` (the entry, regenerated by `uxdsl generate-entry`; do not edit it), and adds `uxdsl:build` and `uxdsl:watch` scripts. It writes no theme file: the base theme is built in. What it printed in an empty project:

<div className="doc-section">

## 3. Build, and keep building

```bash
npx uxdsl build --watch
```

Import the generated `src/uxdsl.css` once, from your root layout or app entry. A broken edit is reported with its `UXD_*` code and line; the last good CSS stays on disk until the next valid save.

To change a token, add `uxdsl.theme.json` next to the config with only what you change — `{ "densities": { "3": "xs(space(2)) md(space(4))" } }` — and every `density(3)` follows. The [Theme](/docs/theme) page lists every family.

## Your framework

The CLI works with any framework. Next.js, Vite and Webpack can also compile `.uxdsl` themselves, through the same pipeline.

<div className="doc-section">

In a Next.js project `init` also writes `postcss.config.js` — Next's own default plugins, which a custom file replaces, then `uxdsl/postcss` with `includeTheme: false` — so CSS Modules can use tokens while the theme comes once from the CLI's `src/uxdsl.css`. Run `npm run uxdsl:watch` next to `next dev`, and import `src/uxdsl.css` from `app/layout.tsx`.

<Tab>

<div className="doc-section">

With no CLI at all, the PostCSS plugin compiles every stylesheet of the app. Keep `includeTheme: false` (the same `postcss.config.js` as above) and write `@uxdsl theme;` once, at the top level of the one global stylesheet: the theme's `:root` is emitted there and nowhere else, so CSS Modules stay free of `:root`.

```text
/* app/globals.css, imported once from app/layout.tsx */
@uxdsl theme;

body { margin: 0; }
```

A misspelled, repeated or nested marker is `UXD_THEME_MARKER`. The theme is the project's `uxdsl.theme.json`, discovered from the working directory.

</div>

// vite.config.js
import { defineConfig } from 'vite'
import uxdsl from 'uxdsl/vite'

```js
// main.js: a .uxdsl import is a CSS import, handled by Vite's own CSS pipeline (HMR, build extraction)
import './styles.uxdsl'
```

Vite 4 and later. The plugin discovers `uxdsl.theme.json` the way the CLI does; `import css from './panel.uxdsl?inline'` returns the compiled CSS as a string.
